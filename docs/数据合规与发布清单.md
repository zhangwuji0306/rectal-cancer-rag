# 数据合规与发布清单

## 本地索引

`index/chroma_db/` 保存向量、元数据和文本块，只允许作为本机私有运行时
数据。它不属于代码发布物，也不得通过 Git、Git LFS、压缩包或备份镜像公开
分发。`converted/`、`mucinous/`、`papers/` 中的论文正文和本地备份同样只保留在受控环境中；
文献元数据、下载与转换状态、入库清单可随代码公开发布。

## 来源与许可证

每条下载任务通过 `License` 字段记录许可证标识或 `unverified`。下载报告同时
生成 `reports/source_licenses.csv`，其中的来源通道不能替代许可证证明。只有能
回查到明确许可、开放获取条款或机构授权的资料，才可纳入可发布语料；其余资料
仅可在机构批准的内部环境使用。

默认下载策略只访问已批准的官方开放获取通道。非 OA 通道需要机构合规/法务书面
确认后，才可在本地配置中显式启用；TLS 校验必须保持开启。

## 发布前检查

1. 远程仓库保持公开，发布范围限于代码、工作流说明和文献状态文件。
2. 在真实 Git 工作副本中备份后，使用经审核的历史重写工具清除
   历史中的 `index/chroma_db` 文件及其 LFS 引用，再强制推送清理后的历史。
   GitHub 端残留的孤立 LFS 对象需联系 GitHub 支持清除；历史重写不等于远端存储对象已删除。
3. 使用全新克隆检查 Git tree、LFS 对象和发布压缩包，确认不存在向量库、文本块、
   PDF、转换后的论文 Markdown 或本地备份；项目说明文档可正常发布。
4. 由机构合规/法务确认每个来源的许可证边界，并保存审计记录。

在这些检查完成前，检索结果只能用于寻找候选论文；结论必须回查原文，不能作为
完整综述、临床决策或自动答案的唯一依据。
